## 系统与软件分发

### Fedora 与 Fedora Minimal

Fedora 是 Linux 发行版，提供内核、软件包和系统维护机制。本仓库中的 Fedora Minimal 指最小化安装方式或软件选择，在此基础上按需添加 niri、DMS 等桌面组件。

### RPM 与 DNF

RPM 是软件包格式及底层包管理工具，DNF 负责从软件仓库解析依赖、安装和更新软件。文档中的 `rpm -q` 用于查询包，`dnf install` 用于安装；软件包名与可执行命令名不一定相同。

### 软件源与 COPR

软件源提供软件包和元数据。COPR 是 Fedora 社区的构建与仓库托管服务，启用某个 COPR 仓库并不表示其中的软件属于 Fedora 官方仓库。

### Flatpak 与 Flathub

Flatpak 是应用打包、分发和运行体系，使用运行时及沙箱机制；具体访问能力取决于应用权限。Flathub 是提供 Flatpak 应用的仓库，两者不是同一个概念。`--user` 和 `--system` 分别涉及用户级与系统级安装范围。[官方介绍](https://flatpak.org/)

### AppImage 与 FUSE

AppImage 将应用及部分依赖打包成可执行文件；桌面菜单集成与更新仍取决于应用或额外工具。FUSE 允许用户空间程序实现文件系统，一些 AppImage 通过它挂载内置镜像；具体依赖取决于 AppImage 类型与运行方式。

## 显示与桌面组成

### Wayland 与合成器

Wayland 是应用与显示服务通信的协议及相关体系。合成器是其中的服务端，负责组合画面、处理输入和管理窗口；niri 是一个具体实现。不同桌面可以采用不同的 Wayland 合成器实现。[官方说明](https://wayland.freedesktop.org/)

### niri

Wayland 合成器，采用可滚动的平铺窗口布局。它负责显示、输入和窗口管理，通常需要配合面板、通知、输入法等组件组成日用桌面。启动关系见[桌面启动流程](桌面启动流程.md)。

### 桌面环境与桌面外壳

桌面环境通常是一组相互配合的组件，例如 GNOME 和 KDE Plasma。桌面外壳侧重面板、启动器、概览等交互界面；DMS 在本文介绍的桌面组合中承担这类职责，niri 则负责合成与窗口管理。

### DMS

DankMaterialShell 的简称，为桌面提供面板、启动器、通知和控制界面等功能。项目使用 Quickshell 构建界面，并提供 `dms` 命令行工具；具体功能与启动方式取决于版本和配置。

### X11、Xwayland 与 xwayland-satellite

X11 是另一套图形窗口系统协议；Xwayland 是运行在 Wayland 环境中的 X server，用于支持 X11 应用。xwayland-satellite 帮助将 Xwayland 的窗口接入合成器；在 niri 中如何启动它取决于版本与配置。

### CSD 与窗口装饰

CSD 指客户端装饰，由应用绘制标题栏、按钮等窗口外观；服务端装饰由窗口管理侧提供。文档中的 `prefer-no-csd` 表达装饰偏好，不代表能强制移除所有应用自己的按钮。

## 登录与会话

### greetd

登录管理器，负责启动登录界面，通过 PAM 协调认证和建立会话，再运行所选用户会话入口。本仓库的配置方案使用 DankGreeter 作为图形登录界面。

### DankGreeter

图形登录界面，程序名为 `dms-greeter`，与 greetd 配合完成账号输入、认证交互及会话选择等操作。它运行在登录阶段，与登录后用户会话中的 DMS 桌面和锁屏需要区分。

### PAM

可插拔认证模块机制。服务通过 PAM 配置调用认证、账户检查和会话处理模块；`pam_systemd` 负责其中与 systemd 用户会话注册相关的集成。

### TTY 与 VT

TTY 泛指终端设备或终端接口，VT 是虚拟终端。文档中的“切换到 TTY 登录”通常指进入文本虚拟控制台；greetd 配置中的 `vt` 指定登录界面使用哪个虚拟终端。

### 用户会话与 niri-session

用户会话包含登录后的一段使用过程及其相关资源。`niri-session` 是 niri 提供的会话启动入口，协调环境准备、合成器启动和退出清理；它与真正运行窗口管理的 `niri --session` 不是同一个角色。

### 登录界面与锁屏

登录界面用于认证并进入用户会话；锁屏用于保护已经运行的会话。两者可以使用相似外观，也可能调用 PAM，但生命周期和运行身份不同。swaylock 与 DMS 锁屏属于后者。

## 服务管理与进程通信

### systemd

系统和服务管理体系。系统实例通常作为 PID 1 管理整机服务；`systemd --user` 管理某个用户的服务。`systemctl --user` 操作用户服务管理器，未指定 `--user` 时默认操作系统服务管理器。

### unit、service 与 target

unit 是 systemd 管理对象的统称。`.service` 描述服务如何运行，`.target` 用来组织单元和同步阶段；`graphical-session.target` 用于图形会话集成，不是一个绘制桌面的进程。

### systemd-logind 与 linger

systemd-logind 管理登录会话、座席及相关设备访问。linger 允许用户服务管理器在没有登录会话时继续存在或随系统启动，因此注销不一定意味着用户服务环境被全部重建。

### D-Bus 与 dbus-broker

D-Bus 是进程间消息通信体系；系统总线连接系统服务，用户总线连接用户应用与服务。dbus-broker 是总线实现之一；总线属于系统范围，并不意味着进程必须以 root 运行。

### IPC 与按需激活

IPC 是进程间通信的统称，D-Bus 是一种具体机制；`dms ipc call` 是 DMS 提供的控制入口。按需激活指请求到来时才启动服务，例如 socket 激活或 D-Bus 激活；无需让所有组件始终提前运行。

## 语言与环境变量

### 环境变量与 environment.d

环境变量是进程获得的键值设置，新进程通常继承启动方的环境。`environment.d/*.conf` 为 systemd 用户服务提供环境设置；文件变化不会自动重写已运行应用的环境。

### locale 与 gettext

locale 描述语言及日期、数字、排序等区域惯例；GNU gettext 是一种程序消息翻译机制。安装 locale 数据、安装翻译资源和安装中文字体分别解决不同问题。

### LANG、LC_* 与 LANGUAGE

`LANG` 提供默认 locale，`LC_*` 针对具体类别，`LC_ALL` 覆盖全部类别。`LANGUAGE` 是 gettext 等机制使用的消息语言偏好列表；它不是“只让图形界面中文”的开关。详细规则见[中文环境配置](中文环境配置.md#语言变量的含义)。

### 字体、字形与 Nerd Fonts

字体提供字符对应的字形；缺少字形可能出现方框。Nerd Fonts 给字体加入常用于终端提示符的图标字形，和中文界面翻译、中文输入法没有直接替代关系。

## 中文输入法

### Fcitx5

输入法框架，连接应用和输入法引擎，管理切换、候选界面等。它可以加载 Rime；更换 Fcitx5 候选框主题主要改变外观。[官方介绍](https://fcitx-im.org/wiki/Fcitx_5)

### Rime 与 fcitx5-rime

Rime（中州韵）是输入法引擎，根据输入方案处理编码、词典和候选。`fcitx5-rime` 将 Rime 接入 Fcitx5，因此框架、接入模块和引擎各有职责。

### 输入方案与雾凇拼音

输入方案规定编码方式、候选处理和相关配置。雾凇拼音是基于 Rime 的配置与词库项目，文档采用的方案名是 `rime_ice`。[项目说明](https://github.com/iDvel/rime-ice)

### 词库、用户词典与语言模型

词库提供词条及相关信息，用户词典保存个人学习数据等内容，语言模型辅助判断词语搭配和候选顺序。输入法配置中提到的万象语法模型属于模型数据，与完整的输入方案承担不同职责。

### Plum

Plum（东风破）是 Rime 配置管理与方案安装工具，用于下载和更新方案等资源。它服务于部署与维护，不需要在日常输入时持续运行。[项目说明](https://github.com/rime/plum)

### 预编辑、候选框与部署

预编辑是尚未提交给应用的输入内容，候选框用于选择转换结果。Rime 的“部署”会重新处理方案等配置资源；修改源配置后，是否生效还需检查部署结果，不能仅凭编辑文件判断。

## 文件与桌面集成

### XDG 目录

XDG 基础目录规范区分配置、数据、状态、缓存和运行时文件。常见默认位置为 `~/.config`、`~/.local/share`、`~/.local/state` 和 `~/.cache`；`XDG_RUNTIME_DIR` 则由会话环境提供，不应写死为某个用户的路径。

### xdg-user-dirs-update

属于 `xdg-user-dirs` 的工具，用于初始化和维护下载、文档、图片等用户目录，并更新 `~/.config/user-dirs.dirs` 中的映射。它处理的是用户常用目录，与 XDG 配置／缓存目录分工不同；语言改变也不等于这些目录必须改名。

### Desktop Entry

通常以 `.desktop` 文件表示的桌面入口，描述应用名称、图标、启动命令等。启动器可据此展示应用；它是配置文件，不是 Shell 脚本，同一应用也可以有多个入口。[官方规范](https://specifications.freedesktop.org/desktop-entry/latest-single/)

### 启动器与 Fuzzel

启动器提供搜索和启动应用的入口。Fuzzel 是 Wayland 启动器，普通模式通常读取 desktop 入口；`--dmenu` 模式接受外部提供的候选列表。DMS 自带启动器是另一种实现。

### portal 与后端

xdg-desktop-portal 为应用提供文件选择、屏幕共享等桌面接口，后端与具体桌面实现对接。Flatpak 应用常使用 portal，其他应用也可能使用；文件选择正常不代表屏幕共享后端也已正确配置。

### GVfs 与文件管理器

GVfs 为使用 GIO 的应用提供挂载、网络位置等文件访问能力。Nautilus、Dolphin、Thunar 等文件管理器提供交互界面；安装文件管理器和具备全部网络访问后端不是同一件事。

### 密钥环与 GNOME Keyring

密钥环用于保存密码等秘密数据，并向获准的应用提供访问。GNOME Keyring 是相关实现；登录时能否自动解锁取决于认证和会话集成，不能只凭已安装软件包判断。

## 终端与界面技术

### 终端模拟器、Shell 与提示符

Alacritty、Kitty 是终端模拟器，负责显示终端内容并传递输入；Bash、Zsh、Fish 是 Shell，解释命令；Starship 生成提示符。更换其中一项不等于替换另外两项。

### GTK

图形界面工具包，用于构建窗口、按钮和其他界面组件，GNOME 生态广泛使用。应用使用 GTK，并不意味着必须运行完整 GNOME 桌面。

### Qt

跨平台应用开发框架，涵盖界面、网络等功能，KDE 生态广泛使用。应用的语言和外观也可能由其自身配置控制。

### QML

用于描述对象、属性和交互的声明式语言，常与 Qt Quick 配合构建界面。DMS 的界面代码使用 QML，QML 本身不是一个桌面环境。

### Quickshell / qs

基于 Qt Quick、使用 QML 构建桌面外壳和组件的工具。`qs` 是其命令行入口之一；DMS 是建立在它之上的具体桌面外壳。[官方介绍](https://quickshell.org/about/)

### Electron

使用 JavaScript、HTML 和 CSS 构建桌面应用的框架，将 Chromium 和 Node.js 集成到应用中。它属于应用实现技术，不能与 AppImage、Flatpak 这样的分发方式混为一谈。[官方介绍](https://www.electronjs.org/docs/latest/)

### GSettings

访问应用设置的一套接口及命令行工具，常见于 GLib／GNOME 生态。设置通过 schema（配置项定义）和键组织，只有读取对应设置的程序才会受影响。例如，`button-layout` 的作用范围取决于应用实现，不能统一控制所有应用的窗口按钮。

### Material / Material Design

Google 的界面设计体系，提供组件、排版、颜色与交互指导。它是设计规范，不是 Linux 桌面组件或必须安装的运行库。

### Material You

Google 提出的个性化设计方向，强调动态配色等体验，并与 Material Design 的演进相关。软件是否支持从壁纸生成颜色、如何应用这些颜色，由具体实现决定。

## 音视频与截图

### PipeWire

用于音视频流处理和连接的基础设施，桌面音频及屏幕共享等功能可能使用它。它负责处理流和设备连接，具体设备选择与策略还需要会话管理器配合。[官方说明](https://docs.pipewire.org/page_session_manager.html)

### WirePlumber 与 pipewire-pulse

WirePlumber 是 PipeWire 的会话／策略管理器，负责设备选择、路由等策略；`pipewire-pulse` 提供 PulseAudio 协议兼容服务，让使用该接口的应用接入 PipeWire。它们承担不同职责。[WirePlumber 官方介绍](https://pipewire.pages.freedesktop.org/wireplumber/)

### 截图、选区与标注工具

grim 用于获取屏幕图像，slurp 用于交互选择区域，Swappy 和 Satty 用于标注编辑。实际能否组合使用取决于合成器支持的协议与工具版本；在 niri 中应按对应配置指南选择截图入口。

### 剪贴板与剪贴板历史

`wl-clipboard` 提供 Wayland 剪贴板读写命令 `wl-copy` 和 `wl-paste`；cliphist 保存和检索剪贴板历史。读写当前内容、保存历史、把内容贴成悬浮窗口是不同功能。

### OCR 与翻译

OCR 将图像中的文字识别成可处理的文本，翻译将文本转换为另一语言。截图工具即使支持 OCR，也不意味着内置翻译、长截图、贴图或录屏。

### Celluloid

基于 mpv 的图形音视频播放器。它是播放应用，与负责音视频流处理的 PipeWire 属于不同层次；使用说明见[音视频播放器](音视频播放器.md)。

## 配置与脚本阅读

### KDL、TOML、YAML 与 JSON

这些是不同的数据／配置格式。本仓库涉及的配置中，niri 使用 KDL，Alacritty 使用 TOML，Rime 使用 YAML，Obsidian 设置使用 JSON；复制片段时应遵守对应语法和层级，不能当成 Shell 命令执行。

### 合并片段与完整配置

合并片段只展示需要加入或修改的字段，完整配置描述整个文件。特别是 Rime 的 `patch:` 和 niri 的配置块，应先查找已有内容，再合并到正确位置，避免覆盖用户设置或重复键。

### 幂等、备份与回滚

幂等意味着重复执行仍保持预期状态，例如不会反复追加同一配置。备份保存旧内容，回滚将状态恢复到修改前；脚本失败自动退出不等于自动回滚。实现细节见[shell 脚本](shell脚本.md)。

### SHA-256 校验

根据文件内容生成摘要，可用于检查传输前后内容是否一致。校验清单本身也需要可信来源；摘要比对不能替代发布者签名验证。命令与示例见[shell 脚本](shell脚本.md#六sha-256-校验)。
