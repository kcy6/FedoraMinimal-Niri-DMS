# 虚拟机：KVM/QEMU + virt-manager

面向本机 Fedora 44 + niri/Wayland 的入门流程。宿主机指真实电脑，客户机指虚拟机内部的系统。除明确标注外，命令都在宿主机终端执行。

## 本机结论

检查日期：2026-10-10。以下为当时的实测状态，内存、磁盘余量会随使用变化。

| 项目 | 实测情况 | 建议 |
| --- | --- | --- |
| 系统 | Fedora Linux 44，x86_64，niri/Wayland | 使用 Fedora 的模块化 libvirt 服务 |
| CPU | Ryzen 7 8845H，8 核 16 线程，支持 AMD-V | 第一台虚拟机分配 2 个 vCPU |
| KVM | `kvm_amd` 已加载，`/dev/kvm` 存在且可访问 | 无需再到 BIOS 开启虚拟化 |
| 内存 | 系统可见约 14 GiB，可用约 6.1 GiB，交换空间已用约 888 MiB | 先分配 3 GiB，一次运行一台；内存是主要限制 |
| 磁盘 | `/` 与 `/home` 共用文件系统，可用约 933 GiB | Linux 虚拟磁盘先设 40 GiB，使用 qcow2 |
| 软件 | virt-manager 5.1.0、QEMU 10.2.2、libvirt 12.0.0 已安装 | 可以跳过安装步骤 |

| 服务 | `virtqemud.socket`、`virtnetworkd.socket`、`virtstoraged.socket` 已启动并启用 | 保留模块化服务，不混用旧的 `libvirtd` 启动方案 |

当前用户已经可以查询系统连接，无需为了照搬教程而添加用户组或修改设备权限。宿主机没有安装 `spice-vdagent` 不是缺项；桌面集成代理通常装在客户机里。

本次维护仅检查环境、编写文档，没有安装系统软件、修改服务配置或创建虚拟机。尚未进行真实客户机启动和联网测试。

## 这些组件分别做什么

- **KVM**：Linux 内核的硬件虚拟化能力，让客户机使用 CPU 虚拟化加速。
- **QEMU**：提供虚拟 CPU、磁盘、网卡等设备，与 KVM 配合运行客户机。
- **libvirt**：管理虚拟机、网络、存储；`virsh` 是它的命令行工具。
- **virt-manager**：图形管理界面，日常创建、启动和调整虚拟机主要用它。
- **ISO**：系统安装光盘镜像；**qcow2**：存放客户机系统与数据的虚拟硬盘文件。

## 1. 检查环境或重装后恢复组件

**本机已经具备这些组件，现在可直接进入第 2 步。** 重装 Fedora 后才需要按下面的顺序补齐。

```bash
sudo dnf install virt-manager qemu-kvm libvirt-daemon-kvm libvirt-daemon-config-network edk2-ovmf swtpm
sudo systemctl enable --now virtqemud.socket virtnetworkd.socket virtstoraged.socket
```

Fedora 本机采用模块化服务，分别管理 QEMU、网络和存储。socket 会按需唤起服务，因此某个 `.service` 显示 disabled 不等于功能不可用。参见 [libvirt 服务说明](https://libvirt.org/daemons.html)。

检查：

```bash
virt-host-validate qemu
virsh -c qemu:///system list --all
virsh -c qemu:///system net-list --all
virsh -c qemu:///system pool-list --all
```

本机硬件虚拟化、KVM 设备、网络设备等关键检查均为 PASS。另有两项 WARN：

- `devices` cgroup 检查警告：本机使用 cgroup v2；不能仅凭此警告认定 KVM 不可用，也不应直接重编内核。如果实际启动失败，再按具体报错排查。
- 未提供 SEV/TDX 等安全客户机能力：普通桌面虚拟机不要求这些机密计算功能。

## 2. 准备安装镜像

第一次建议先装熟悉的 Linux，例如 Fedora 或 Ubuntu。下载 **x86_64/amd64 的桌面安装 ISO**，不要误选 ARM 镜像或面向云平台的磁盘镜像。

在发行版官方网站下载 ISO，并按下载页说明核对校验值。将它放到默认存储目录，可以减少家目录访问权限和 SELinux 标签问题。

下面第一行需要替换为真实文件路径；目标文件名 `installer.iso` 后续在界面中选用。若已有同名文件，`cp -i` 会询问是否覆盖。

```bash
iso_path="$HOME/Downloads/替换为实际镜像文件名.iso"
sudo cp -i -- "$iso_path" /var/lib/libvirt/images/installer.iso
sudo chmod 0644 /var/lib/libvirt/images/installer.iso
sudo restorecon -v /var/lib/libvirt/images/installer.iso
```

## 3. 打开管理器并选择系统连接

在应用启动器搜索“Virtual Machine Manager / 虚拟系统管理器”，或运行：

```bash
virt-manager --connect qemu:///system
```

以普通用户启动；出现认证窗口时按提示认证。应看到本地 **QEMU/KVM** 连接。

如果需要手动添加：菜单“文件 → 添加连接”，选择 QEMU/KVM、本地连接，使用系统连接。本文所有命令均显式指定 `qemu:///system`，避免和 `qemu:///session` 混淆；两者的虚拟机列表、网络和权限环境不同。

## 4. 创建第一台 Linux 虚拟机

点击“新建虚拟机”，按向导操作。不同语言和版本的按钮文字可能略有差别。

1. 选择“本地安装介质（ISO 镜像或光盘）”。
2. 点击“浏览”，在 `default` 存储池选择 `installer.iso`。文件未显示时刷新存储池。
3. 检查操作系统识别结果；无法自动识别时，手动选对应发行版和版本。
4. 内存填 **3072 MiB**，CPU 填 **2**。
5. 创建 **40 GiB** 虚拟磁盘，格式使用 **qcow2**，放在默认存储池。
6. 名称设为容易识别的名字，如 `linux-test`；勾选“安装前自定义配置”。
7. 网络选择 **Virtual network 'default': NAT**。
8. 在硬件详情中核对下面的参数，然后点击“开始安装”。

| 参数 | 第一台 Linux 虚拟机建议 |
| --- | --- |
| 虚拟化类型 | KVM |
| CPU | 2 vCPU；模型先用向导默认值 |
| 内存 | 3072 MiB；轻量服务器可用 2048 MiB |
| 固件 | 新建时可选 UEFI；安装完不要随意切换 BIOS/UEFI |
| 磁盘总线 | VirtIO，现代 Linux 一般内置驱动 |
| 网卡型号 | VirtIO |
| 显示协议 | SPICE |
| 视频设备 | Virtio；首次安装先不开 3D 加速 |
| 网络来源 | default NAT |

qcow2 通常按实际写入增长，40 GiB 是客户机可见容量，不意味着立即占满 40 GiB；快照会额外占空间。

进入安装器后，按普通电脑安装系统的流程操作。这里的“擦除磁盘”应指向向导创建的 **40 GiB 虚拟磁盘**；先核对大小。本文不添加物理磁盘直通。

安装完成后重启。如果再次进入安装界面，在虚拟机硬件详情的 CD-ROM 中弹出 ISO，或将虚拟硬盘设为优先启动设备。

## 5. 安装客户机集成工具

**下面的安装命令在虚拟机内部执行。**

Fedora 客户机：

```bash
sudo dnf install spice-vdagent qemu-guest-agent
```

Ubuntu/Debian 客户机：

```bash
sudo apt update
sudo apt install spice-vdagent qemu-guest-agent
```

- `spice-vdagent`：支持剪贴板、分辨率调整等桌面集成；实际效果还取决于客户机桌面及 Wayland/X11 支持。
- `qemu-guest-agent`：让宿主机获取客户机信息并执行协作管理操作，不负责剪贴板。

在关机状态检查硬件详情，缺少时通过“添加硬件 → 通道”补充：

- SPICE agent 通道：`com.redhat.spice.0`。
- QEMU guest agent 通道：`org.qemu.guest_agent.0`。

重新启动客户机，在客户机内检查并启动 QEMU agent：

```bash
sudo systemctl start qemu-guest-agent
systemctl status qemu-guest-agent --no-pager
```

SPICE 桌面代理通常随图形会话启动；安装后注销客户机桌面再登录。若剪贴板仍不工作，检查显示协议、通道和客户机桌面兼容性，不要把代理装到宿主机当作修复。参见 [SPICE 使用手册](https://spice.pages.freedesktop.org/spice-space/spice-user-manual.html)。

## 6. 网络与上网

本机默认路径是：客户机 → `virbr0`（`192.168.122.1`）→ 宿主机 NAT → Wi-Fi。客户机通过 DHCP 获取 `192.168.122.x` 地址。

- 客户机可通过 NAT 主动访问外网；宿主机一般可访问客户机 IP，具体服务还需客户机防火墙放行。
- 同一 Wi-Fi 下其他设备默认不能主动访问客户机；需要这种需求时再配置端口转发或其他网络方案。
- Wi-Fi 环境优先沿用 NAT；先不尝试把无线网卡加入普通以太网桥。
- 宿主机存在活动的 TUN 接口，但这不能证明客户机流量一定经过代理。宿主机浏览器代理、`127.0.0.1` 代理地址不会自动传入客户机；以客户机实际联网结果为准。

从宿主机查看 DHCP 租约：

```bash
virsh -c qemu:///system net-dhcp-leases default
```

如果网络存在但状态为 inactive，才执行：

```bash
sudo virsh -c qemu:///system net-start default
sudo virsh -c qemu:///system net-autostart default
```

本机已是 active，无需重复启动。如果提示网络不存在，在 virt-manager 的连接详情 → 虚拟网络中创建 NAT 网络，或检查 `libvirt-daemon-config-network` 包。参见 [libvirt 默认网络排错](https://wiki.libvirt.org/Virtual_network_default_has_not_been_started.html)。

## 7. 如果要安装 Windows 11

本机 CPU 足够，主要要控制内存占用。建议关闭较占内存的软件后，先用 **4 vCPU、6 GiB 内存、80 GiB qcow2**；保留至少约 4 GiB 可用内存给宿主机和其他程序。以当前约 6 GiB 可用内存的状态，不宜直接再分配 6 GiB。

创建前准备 Windows 官方 ISO 和 [Fedora 提供的 Windows VirtIO 驱动](https://fedoraproject.org/wiki/Windows_Virtio_Drivers)。

1. 操作系统类型选择 Windows 11，安装前进入自定义配置。
2. 配置支持 Secure Boot 的 UEFI 固件，并核实安全启动启用；添加 **TPM → 模拟器 → 2.0**。本机已有 OVMF 和 swtpm 软件包，但具体虚拟机仍需配置这些设备。
3. 额外挂载 VirtIO 驱动 ISO 为第二个 CD-ROM。
4. 如果安装器看不到 VirtIO 磁盘，点击“加载驱动”：VirtIO Block 用 `viostor`，VirtIO SCSI 用 `vioscsi`，选对应 Windows 版本的 amd64 目录。
5. 如果网卡不可用，安装驱动 ISO 中对应版本的 `NetKVM` 驱动；进入系统后可运行其中的 `virtio-win-guest-tools.exe` 完善驱动与代理。

不熟悉磁盘驱动时，可以从 SATA 虚拟磁盘起步；已经装好系统后，不要在未准备驱动的情况下直接切换启动盘总线。Windows 客户机不能因为宿主机有 Radeon 780M 就自动获得这块显卡的性能；游戏和 GPU 直通属于后续独立配置。

## 8. 日常使用与验收

正常关闭：在客户机内关机，或使用管理器的“关闭系统”。“强制关闭”类似拔电源，仅在无响应时使用。

首次安装后的验收：

- 能从虚拟硬盘启动，不再回到安装器。
- 在客户机浏览器里可以打开网页。
- 调整窗口时检查分辨率效果；测试复制一段普通文本。
- 客户机正常关机后可以重新启动。
- 宿主机执行 `free -h`，观察是否明显增加交换空间占用、桌面是否卡顿；必要时减少客户机内存或关闭其他程序。

大改系统前，可在关机后通过快照界面创建快照（以当前磁盘与固件配置支持为准）。**快照不能代替备份**。备份应在关机后保存虚拟磁盘、虚拟机 XML；UEFI/TPM 客户机还需保存对应 NVRAM 和 TPM 状态，只复制 qcow2 不一定能完整恢复。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 无法连接 QEMU/KVM | 连接是否是 `qemu:///system`；`systemctl is-active virtqemud.socket` |
| 认证没有窗口或提示权限不足 | niri 会话是否有可用的 polkit 认证代理；不要直接改成长期用 root 运行图形管理器 |
| 找不到 default 网络 | 是否误连到了 session；系统连接中查看 `net-list --all` |
| ISO 报 Permission denied | 是否放在默认存储目录、可读权限是否正确、是否执行了 `restorecon`；不要关闭 SELinux |
| 存储列表第一次打开较慢 | 存储服务可能正在被 socket 唤起；检查 `virtstoraged.socket` 和服务日志 |
| 黑屏或图形异常 | 先关闭虚拟机 3D 加速，检查视频设备与客户机驱动 |
| 装好后仍进入安装界面 | 弹出 ISO，检查硬盘启动顺序 |
| 宿主机卡顿 | 优先检查可用内存与交换空间，而不是给客户机增加 CPU |

服务排错日志：

```bash
journalctl -b -u virtqemud -u virtnetworkd -u virtstoraged --no-pager -n 100
```

维护本文时，重新执行第 1 步检查命令，并更新“本机结论”的日期与实测状态；区分“环境检查通过”和“实际虚拟机启动通过”。
