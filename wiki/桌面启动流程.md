# 桌面启动流程

本文以 Fedora 上的 greetd、DankGreeter、niri 和 DankMaterialShell（DMS）组合为例，介绍从系统启动到进入桌面的过程，以及环境变量如何传递给应用。术语解释见[部分概念](部分概念.md)，语言设置步骤见[中文环境配置](中文环境配置.md)。

**适用范围：** 使用 systemd 的 Fedora 常规安装、Wayland 桌面。其他登录管理器、发行版或会话管理方式可能不同。

## 组件职责

| 组件                         | 职责                       |
| -------------------------- | ------------------------ |
| 系统 systemd（PID 1）          | 管理系统服务及其依赖               |
| systemd-logind             | 管理登录会话、座席与设备访问           |
| PAM                        | 按服务配置执行认证与会话建立等操作        |
| greetd                     | 启动 Greeter，协调认证并启动所选用户会话 |
| DankGreeter（dms-greeter）   | 提供登录界面                   |
| 用户 systemd（systemd --user） | 管理该用户的服务和服务启动环境          |
| niri                       | Wayland 合成器，管理显示、输入和窗口   |
| DMS                        | 提供面板、启动器、通知和其他桌面界面       |
| Quickshell（qs）             | 运行 DMS 的 QML 界面          |

DankGreeter 提供登录前的认证界面，DMS 锁屏则保护已经运行的用户会话。两者处于不同阶段。

## 从开机到登录界面

```text
固件 → 引导程序 → Linux 内核 → 系统 systemd
                                  ├─ 设备、网络等系统服务
                                  ├─ systemd-logind、系统 D-Bus
                                  └─ greetd → DankGreeter + 登录界面用的 niri
```

以下为参考环境中 `/etc/greetd/config.toml` 的关键配置片段。运行账户、虚拟终端和配置路径应与实际安装方式一致。

```toml
[terminal]
vt = 1

[default_session]
command = "/usr/bin/dms-greeter --command niri --cache-dir /var/cache/dms-greeter -C /etc/greetd/niri/config.kdl"
user = "greeter"
```

- `vt = 1` 指定登录界面使用的虚拟终端。
- `user = "greeter"` 指定登录界面的运行账户。
- `--command niri` 指定登录界面使用的合成器。
- `-C` 指向登录界面用的 niri 配置。

登录界面中的 niri 和登录后运行的 niri 是不同实例，使用不同身份和配置。普通用户的语言环境不会自动成为 `greeter` 用户的语言环境。DankGreeter 的部署方式与参数应以对应版本的[官方安装文档](https://danklinux.com/docs/dankgreeter/installation)为准。

## 从登录到用户桌面

参考环境中的 Niri 会话文件 `/usr/share/wayland-sessions/niri.desktop` 使用 `Exec=niri-session` 指定启动入口，对应脚本为 `/usr/bin/niri-session`。选择该会话后，主要流程如下：

```text
greetd 完成认证并建立用户会话
  ↓
启动所选会话入口 niri-session
  ↓
准备登录环境，将环境导入用户服务管理器和 D-Bus 激活环境
  ↓
请求 systemd --user 启动 niri.service
  ↓
niri --session 运行，建立图形会话集成
  ↓
已配置的 DMS 等桌面服务启动，应用可以连接显示服务
```

### niri-session、niri.service 和 niri --session

| 名称 | 类型 | 作用 |
| --- | --- | --- |
| `niri-session` | 会话启动脚本 | 协调环境准备、服务启动、等待退出和清理 |
| `niri.service` | systemd 用户服务定义 | 描述如何启动及管理合成器 |
| `niri --session` | 合成器进程及其启动参数 | 运行 niri 并启用会话集成 |

脚本在常规 systemd 启动分支中，会经过登录 Shell、检查重复会话、导入环境，并执行 `systemctl --user --wait start niri.service`。会话结束后启动 `niri-shutdown.target`，再清除显示连接等会话变量。

TTY 手动启动与图形登录可以使用同一入口：前者由登录 Shell 执行 `niri-session`，后者由登录管理器启动所选会话。手动启动适用于尚未运行图形会话的情形。

## 桌面组件如何启动

参考环境中，`niri.service` 的 `ExecStart` 是 `niri --session`，与 `graphical-session.target` 关联。`dms.service` 的 `ExecStart` 是 `dms run --session`，同样关联到图形会话，并配置了失败后重启。

```text
用户服务管理器
  ├─ niri.service → niri --session
  ├─ dms.service → dms → Quickshell 界面
  └─ 音频、portal 等用户服务
```

这表示服务管理关系，不表示所有程序都由 niri 直接创建。DMS 在其他安装方式中也可能通过合成器的启动配置运行，应根据实际安装方式检查启动关系。

| 配套组件 | 用途 | 常见启动途径 |
| --- | --- | --- |
| Fcitx5 | 输入法框架 | 合成器启动配置或桌面自启动项，避免重复启动 |
| PipeWire、WirePlumber | 音视频处理与设备策略 | 用户服务、socket 激活 |
| xdg-desktop-portal 及后端 | 文件选择、屏幕共享等桌面接口 | D-Bus 激活和用户服务 |
| 密钥环服务 | 保存和访问凭据 | PAM 集成或按需激活，取决于安装配置 |
| GVfs | 桌面文件访问与网络位置 | 按需激活 |
| xwayland-satellite | 支持 X11 应用 | 取决于 niri 版本与配置 |

上表概括各组件的职责和常见启动方式。具体依赖可参考 niri 的[配套软件说明](https://niri-wm.github.io/niri/Important-Software.html)。

## 环境变量如何传递给应用

`environment.d` 是 systemd 用户服务环境机制，并非 niri 专用配置。默认用户配置目录是 `~/.config/environment.d/`；使用自定义 `XDG_CONFIG_HOME` 时，该变量必须在环境生成器确定目录之前就已可用。

```text
用户 environment.d/*.conf
  ↓ 用户环境生成器读取
systemd --user 提供给新服务的环境
  ├─ niri.service → niri 启动的程序
  └─ dms.service → DMS 启动的程序（具体路径依启动实现而定）
```

需要区分三个层次：

1. **配置文件**表达希望设置的值。
2. **用户服务管理器环境**决定新启动服务可以获得的值。
3. **具体进程环境**是该进程启动时继承或自行修改后的值。

会话脚本导入的登录环境、服务自己的 `Environment=` 和应用内部设置也可能影响最终结果。修改文件不会自动改变已经运行的程序；通过 D-Bus 或其他服务间接启动的应用也不一定沿用当前终端的环境。

配置格式及加载规则可通过 `man environment.d` 查看，也可查阅 [systemd 官方手册](https://www.freedesktop.org/software/systemd/man/latest/environment.d.html)。语言变量的含义、配置和检查见[中文环境配置](中文环境配置.md)。

### 系统 D-Bus 与用户 D-Bus

- **系统 D-Bus**用于访问 NetworkManager、logind 等系统服务。
- **用户 D-Bus**用于桌面应用、通知和用户服务之间的通信。

“系统总线”描述其作用范围，不意味着总线进程一定由 root 运行。D-Bus 的服务激活环境与 systemd 用户服务环境需要区分；参考版本的 `niri-session` 会分别处理这两类环境的导入。

## 只读检查方法

以下命令在当前图形会话的终端中执行，不加 sudo，不会修改服务状态。

```bash
systemctl status greetd --no-pager
systemctl --user status niri.service dms.service --no-pager
systemctl --user cat niri.service dms.service
```

预期：使用本文启动方式的机器上，niri 与 DMS 服务处于 `active`，服务定义的启动命令与安装方式相符。若提示找不到单元，应先确认该组件是否通过其他方式启动。

只查看语言相关环境，避免输出整个环境中的敏感值：

```bash
systemctl --user show-environment | grep -E '^(LANG|LANGUAGE|LC_[A-Z_]+)='
```

排查本次开机的服务错误：

```bash
journalctl --user -b -u niri.service -u dms.service --no-pager -n 80
```

分享日志前应检查其中的应用路径和个人信息。以上命令均为只读检查。
